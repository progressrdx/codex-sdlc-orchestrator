# 测试判断：选择能揭示故障的证据

用于选择测试策略、处理矛盾结果或形成质量结论。目标不是增加用例数，而是区分「目标真的成立」与「这个检查恰好通过」。保持独立测试边界，不改生产代码、不自行降低验收标准。

## 先问怎样会错，再决定怎样测

从一条实际承诺或高影响风险出发：可能怎样失败？哪一层最低成本就能暴露该机制？用什么独立预言判定结果？替身或环境隐藏了什么？还需哪条真实入口证据？将答案写入已有测试计划，不要求每个用例重复一套仪式。

| 场景和风险 | 有区分力的验证 | 不能据此宣布通过 | 何时扩大或改变验证 |
|---|---|---|---|
| 确定性的范围/舍入/格式规则 | 依据需求选择边界、等价类及不变量；以独立计算或已确认样本为预言，优先单元层 | 从被测实现复制同一个算法生成期望；只测常规样本 | 若真实入口还有解析、单位、区域设置或持久化转换，补对应集成/入口检查 |
| 并发、重试、重启可能重复外部副作用 | 控制请求交错、超时后成功、进程重启与恢复；核对最终持久状态及实际副作用数量 | 顺序调用两次都返回 200；mock 每次返回成功；只看日志“已去重” | 内存状态无法代表持久化或外部系统时，补授权范围内的真实契约/集成证据 |
| 数据迁移或版本兼容 | 使用代表性历史数据，核对数量、关联、业务不变量；模拟中断/恢复和并存版本读写 | 迁移命令退出 0；新库空数据测试；应用降级即可证明数据恢复 | 有不可逆转换时验证备份恢复/前向修复边界；不可安全执行的部分记 blocked，不冒险操作生产 |
| 模型/启发式的语义结果 | 区分确定性契约与质量评估；使用有代表性且含反例的样本、可审阅预言，记录版本和不确定性 | 几个演示样本、schema 正确、非空输出或模型自评高分 | 有歧义则先解决判定口径；样本暴露新失败类型时补覆盖，不编造总体准确率 |
| UI 调整涉及主任务、密度或交互 | 用真实规模和关键状态完成任务；在所需视口核对可见信息、输入、反馈与恢复，保留截图/交互证据 | 只有静态截图或“更简洁”；把熟悉的表格、高密度信息本身判为缺陷 | 专家批量比较和低频单步任务需要不同证据；主观偏好交由用户，不伪装为客观缺陷 |
| 测试偶发失败后重跑变绿 | 保留第一次失败，核对同一基线/环境，控制时序与共享状态，分类产品缺陷、测试缺陷或环境阻塞 | 重跑通过就删除失败；用隔离/跳过用例抵消仍未解释的产品风险 | 若无法隔离原因，报告结论不确定及最小后续实验，不把未知记 pass |

## 有限时间内的取舍

先测会损害核心目标、数据/权限安全、难恢复且此次变更触及的风险，再测低影响展示细节。可探测性差会提高验证需求，但不能据此认定故障必然发生。区分「可能性有历史/变更依据」和「尚不清楚」。

时间不足时给出已执行覆盖、未覆盖暴露、减少不确定性所需的最小工作和当前 verdict。不得把 Must 改成可选、把阻塞改成通过，或以“风险较低”自行批准用户尚未接受的风险。无需把同一断言机械复制到单元、集成、端到端每一层；每层应证明不同的故障机制或真实连接。

## 预言要独立，结论要有边界

- 先定义预期业务含义再运行。未知/空值/失败不能混为零；成功提示与实际数据冲突时，以已确认契约和事实来源裁定。
- 替身适合稳定重现失败分支；它省略的认证、序列化、持久化、权限和下游语义必须明确。依赖不可访问时可以交付局部验证，不能声称核心集成已验收。
- 对差异先对齐输入、版本、启动入口和环境，再定位。测试声称 pass 而实际旅程失败，不以测试数量投票。
- 区分 fail（可观察违约）、blocked（无法取得必要证据）、需求歧义、测试缺陷和不适用；不适用必须符合已批准范围，不能用来掩盖未执行。

交接一个发现时，提供最小复现、预言依据、实际结果、影响、当前源码/环境和下一项能区分原因的检查。建议修复方向可供工程参考，但不能越权实施修复，也不能从未经测试的代码推断“已解决”。
