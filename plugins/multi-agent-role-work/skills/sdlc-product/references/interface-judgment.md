# 从任务模型选择界面

用于产品定义、信息架构、原型方向和 UI 反馈分析。先决定怎样帮助用户工作，再决定外观。下面是有条件的起点，不是“某行业必须使用某模板”的规则；已有产品约束和真实使用证据优先。

## 先识别工作方式

从需求与现有产品中提取会改变界面选择的事实。缺失时区分可逆假设与必须询问的决策，不把下列维度变成问卷：

- **用户与频率**：新手偶尔使用，还是熟练用户每天持续操作？同一产品可能两者都有。
- **核心动词与对象**：寻找、比较、处理、编辑、配置、监控或批准什么？是一件事，还是大量同类对象？
- **同时可见的依据**：哪些字段、上下文、对照内容必须一起看到，才能作出判断？
- **过程与代价**：短操作还是长会话？是否等待异步结果？误操作能否恢复，影响哪些对象？
- **场景约束**：桌面键鼠、手机触控、受限屏幕、已有组件与用户习惯。

输出一条可追问依据的推理链：**场景事实 → 主导工作方式 → 结构 → 密度与披露 → 取舍 → 验证任务**。不要只给“简洁、专业、高级”的形容词。复杂产品按任务/页面分类，不强求全站使用同一个结构。

## 工作方式到结构的候选映射

| 工作方式与成立条件 | 优先考虑的结构 | 首先保留的信息/操作 | 何时不适用或需要调整 |
|---|---|---|---|
| 单次输入到输出：计算、转换、格式处理，输入与结果直接对应 | 紧凑输入区 + 结果区，常用动作靠近输入；低频参数按需展开 | 输入约束、结果、进度/错误、复制或导出 | 大批文件需要队列、逐项状态和部分失败重试，不能只留一个执行按钮 |
| 高频同类对象处理：工单、订单、资源管理；反复筛选和跨行比较 | 列表/表格 + 搜索筛选 + 详情面板；有真实批量任务时提供选择和批量操作 | 识别字段、决策字段、异常状态、当前选择范围；返回后保留筛选与位置 | 视觉辨认占主导时考虑缩略图网格；不要为整齐把比较字段折叠，也不要把每一行做成大卡片 |
| 监控与异常处置：持续看状态，异常时介入 | 异常优先的总览 + 事件列表 + 定位到处置对象 | 严重程度、影响、数据新鲜度、确认/处置状态 | 若用户需要比较原因与变化，进入分析视图；没有处置用途的指标不占主视区 |
| 分析与比较：按维度解释变化、检验假设 | 有语义的图表/表格 + 共用筛选 + 对照/下钻 | 时间范围、单位、比较基准、筛选状态、来源与不确定性 | 不用一排 KPI 代替分析；单一精确查询可能只需搜索和结果，不必做仪表盘 |
| 持续编辑与创作：文档、设计、代码、时间线等长会话 | 对象/画布为主，相关工具与属性围绕选中内容，保留定位和撤销 | 工作内容、选择/模式、保存状态、预览与恢复 | 不把常用工具藏入层层展开，不用向导打断连续操作；新手帮助可逐步披露 |
| 低频配置或分步申请：依赖条件多、需要引导与纠错 | 按语义分组的表单；只有顺序依赖或负担确有需要时使用分步流程 | 当前条件、校验、影响说明、返回修改、保存/提交状态 | 熟练用户频繁修改相互关联字段时，单页分组可能更合适；不是每个字段都要一页 |
| 决策与审批：需要理解证据、影响后选择 | 决策摘要 + 相关证据/差异 + 明确的批准/退回等动作 | 对象、变更内容、影响范围、必要风险和理由 | 低风险单项可聚焦一个决定；高风险不能为“简洁”隐藏后果；大量审批还需队列与跨项上下文 |
| 查找、阅读、学习：以内容消费与检索为主 | 内容主体 + 与任务相符的目录、搜索或结果筛选 | 内容、定位、阅读进度/来源（需要时） | 视觉浏览可用媒体网格；持续编辑应转为编辑工作区，不把内容挤到侧栏 |
| 了解与转化：陌生访客评估产品或服务 | 叙事、价值证据与行动路径 | 用户要解决的问题、可信证据、下一步 | 登录后工作不应反复经过营销首屏；品牌表达不能替代可操作的产品入口 |

“AI 工具”不是独立布局类型：对话用于目标澄清或迭代指令；精确参数仍可用表单，批处理仍需队列，生成内容仍需可查看、编辑与比较的结果区。只有任务适配时才让聊天记录成为主界面。

## 决定保留、披露与密度

对会影响布局的内容分三类，不必为每个标签写长表：

- **工作必需**：当前对象、比较依据、常用操作、状态与关键后果。放在执行任务时可见或直接可达的位置。
- **辅助诊断/低频配置**：确实有用，但不参与每次判断。放入有明确名称的详情、展开区或独立页面，保留可发现入口。
- **没有任务价值**：重复摘要、无后续动作的指标、占据工作区的口号和装饰。移除或移到适合的品牌场景。

披露会增加寻找、点击与记忆成本。若用户要反复对照、批量操作或持续监控，隐藏内容可能让界面更空却更难用。高密度也不能以小字、挤压触控区域和含混分组为代价。用合理列、对齐与稳定分组提高可读性，不把“留白多”当作质量指标。

“一个主操作”指当前任务的视觉优先级，不是整个专业工具只能有一个按钮。保留常用工具、撤销、返回和必要导航；将全局、对象级与批量操作的作用范围分清。

## 先比较结构，再讨论风格

在已有 PRD 或方向说明中简短记录：选择的工作方式及依据、主工作区、必要上下文、披露策略、最接近的替代结构及放弃原因。一个明确任务用几句话就够；真实结构分歧才值得画对比草图。

有成熟模式时沿用用户习惯。颜色、字体、圆角和品牌识别应建立在任务结构之上；无需为了“看起来不同”重新发明表格、导航或编辑器。外部设计 Skill 的风格建议若不适配任务，应说明原因并不用，而不是套用后要求用户纠偏。

## 用任务验证选择

给工程与测试可执行的走查，不用主观形容词或元素数量代替验收：

- 找到目标对象、取得判断依据、执行动作、理解结果、恢复或继续下一项。
- 使用具有代表性的对象数量、字段长度、异常和会话状态；大数据列表不能只用三条完美样本验证。
- 验证被折叠的信息是否真的低频；比较、批量处理、返回定位和状态保留有没有被视觉简化破坏。
- 对照候选结构时观察误解、遗漏、来回切换、恢复和重复任务成本。没有实测就写“待验证”，不编造节省时间或效率提升比例。
- 手机场景保留必要任务，不机械缩小桌面，也不以响应式为由静默删除已承诺能力。需不同交互或限制时明确说明并确认。

## 从反馈提炼能力，而不是固化样式

先判断反馈对象：本次页面、当前产品的约束，还是用户在检验产品角色/Skill 的判断能力。用户要求总结经验时，交付可迁移的判断与反例；不要擅自把任务继续解释为像素修改。

对“杂乱、重点不突出、还可优化”，先提出可检验原因：任务选错、比较依据被打散、优先级冲突、模式不熟悉，还是仅对齐与文案问题。修正对应层级。结构不合适时换配色无效，必要信息不足时继续删除也无效。

### Project Compass 案例的适用边界

观察：示例把品牌、装饰指南针、目标、阶段、标签、决策等同时展示，用户认为元素多且重点不突出。聚焦待办、按需展开资料后，用户评价接近预期，但仍可优化。随后用户明确目标是提升产品 Skill，而不是继续修改这一个页面。

可迁移经验：先问清当前工作任务；让信息优先级服务于操作；把对示例的反馈变成有条件的决策规则。后续精简版只展示了一个决策，不足以证明完整项目管理工具应如此设计，也未证明在多项目、多待办、证据比较或异常处理中更有效。

不应沉淀为规则：所有工具只有一个主按钮、所有记录默认折叠、禁止表格/卡片/仪表盘、绿色配色就是专业。更不能把用户对简洁度的认可当成所有任务已经通过验收。

## 有边界的外部依据

查阅日期：2026-08-27。以下只支持相应局部模式，上表是结合任务模型的产品判断，不是这些设计系统给出的统一分类或强制规范。

- [Carbon：Data table](https://carbondesignsystem.com/components/data-table/usage/)：支持结构化数据、排序、选择和批量操作；补充信息可展开，但复杂电子表格编辑不是数据表组件的替代用途。
- [GOV.UK：Question pages](https://design-system.service.gov.uk/patterns/question-pages/)：在问答型服务中以单问题页面作为起点，保留返回修改；进度提示取决于用户研究。这不意味着所有专业配置或操作工具都应使用向导。
